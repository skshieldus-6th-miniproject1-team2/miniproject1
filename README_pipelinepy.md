# 서울 아파트 실거래가 전처리 파이프라인 (`pipeline.py`)

> 이 문서는 `pipeline_v1_original.py`(gu_summary 기능 추가 이전 원본)와 짝을 이루는 버전입니다.
> 최신 버전은 `README.md`(`pipeline_v2_gu_summary.py`용)를 참고하세요.

국토교통부 실거래가 공개 CSV(구 단위, 정책전/정책후로 분리된 파일)를 읽어 하나의 스키마로
병합·정제하고, 분석에 바로 쓸 수 있는 마스터 테이블과 집계본을 생성하는 스크립트.

## 목적

정부 부동산 정책 시행 전후 서울 지역 아파트 매매가 변동을 분석하기 위한 전처리 단계.
- 지역별(구·동) 평단가 변동률 분석
- 향후 머신러닝 기반 매매가 예측

## 요구 사항

```
python >= 3.9
pandas
numpy
```

## 입력 데이터

`--raw-dir` 폴더 안에 다음 파일명 규칙을 따르는 CSV들을 넣는다.

```
{구}_{정책전|정책후}_{시작일:YYYYMMDD}_{종료일:YYYYMMDD}.csv
예) 강남구_정책전_20240507_20250627.csv
```

각 CSV는 국토교통부 실거래가 다운로드 시의 원본 컬럼(20개)을 그대로 가지고 있어야 한다.
필수 컬럼 목록은 `RAW_COLUMNS`에 정의되어 있으며, 하나라도 없으면 `ValueError`로 즉시 중단한다.

```
NO, 시군구, 번지, 본번, 부번, 단지명, 전용면적(㎡), 계약년월, 계약일,
거래금액(만원), 동, 층, 매수자, 매도자, 건축년도, 도로명,
해제사유발생일, 거래유형, 중개사소재지, 등기일자
```

## 사용법

```bash
python pipeline.py --raw-dir seoul_raw_data --out-dir processed
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--raw-dir` | `seoul_raw_data` | 원본 CSV가 들어있는 폴더 |
| `--out-dir` | `processed` | 결과 파일을 저장할 폴더 (없으면 자동 생성) |

## 처리 단계 (`clean()` 함수 기준)

1. **로드** (`load_raw`) — `raw_dir`의 모든 CSV를 파일명에서 구/정책여부/종료일을 파싱해 하나로 병합. 파일 수정시각·종료일 순으로 정렬해 이후 dedup에서 최신 파일이 우선하도록 함.
2. **계약취소 제외** — `해제사유발생일`이 비어있지 않은 행 제거.
3. **완전 중복 제거** — `NO`를 제외한 전체 컬럼 기준 `drop_duplicates(keep="last")`.
4. **타입 변환 및 파생변수 생성**
   - `거래금액(만원)` 문자열 → 정수
   - `계약년월` + `계약일` → `계약일자` (datetime)
   - `시군구` → `구` / `법정동` 분리
   - `평형` = 전용면적 ÷ 3.3058, `평단가` = 거래금액 ÷ 평형
   - `연식` = 계약연도 − 건축년도
5. **재수집 중복 해소** (`resolve_business_key_duplicates`) — 아래 "Business Key 로직" 참고.
6. **이상치 플래그** (`flag_outliers`) — 아래 "이상치 판정 로직" 참고. 삭제하지 않고 `이상치여부` 컬럼만 추가.
7. **의심 중복 리포트** — `NEAR_DUP_KEY` 기준 리포트 생성 (자동 처리 없음).
8. **구×동×월 집계** (`aggregate_monthly_price`) — 별도 파일로 저장.

## Business Key 로직

재수집(같은 기간을 다른 시점에 다시 받는 경우) 시 동일 거래가 정보량만 다르게 중복 신고될 수
있는 문제를 해소하기 위한 로직.

```python
BUSINESS_KEY = ["구", "법정동", "단지명", "계약일자", "층", "거래금액"]

BUSINESS_KEY_CONFLICT_COLS = [
    "동", "매수자", "매도자", "도로명", "거래유형", "등기일자", "전용면적(㎡)",
]
```

`BUSINESS_KEY`가 겹치는 행 그룹에 대해:
- `BUSINESS_KEY_CONFLICT_COLS`의 non-null 값이 그룹 내에서 전부 일치 → 같은 거래의 중복 신고로
  간주, 정보량(non-null 개수)이 가장 많은 행 하나만 유지 (`business_key_dedup_removed.csv`에
  제거된 행 기록)
- 하나라도 값이 다름 → 서로 다른 세대의 거래일 가능성이 있어 병합하지 않고 둘 다 보존
  (`business_key_conflicts.csv`에 기록, 마스터에는 그대로 남음)

## 이상치 판정 로직

```python
PYEONG_DIVISOR = 3.3058
AREA_BIN_WIDTH = 20      # 전용면적 구간 폭(㎡)
MIN_GROUP_SIZE = 5       # 이보다 작은 그룹은 판정 보류
```

`구 × 전용면적 20㎡ 구간`으로 그룹을 나눈 뒤, 그룹별로 평단가에 IQR(사분위수 범위) 규칙을
적용한다.

```
lower = Q1 − 1.5 × (Q3 − Q1)
upper = Q3 + 1.5 × (Q3 − Q1)
```

전체를 한 그룹으로 두지 않는 이유는 지역별 가격 수준 차이와 소형 평형의 높은 평단가 경향을
반영하기 위함. 그룹 크기가 `MIN_GROUP_SIZE` 미만이면 IQR이 불안정해지므로 판정을 보류(항상
`False`)한다. **삭제하지 않고 `이상치여부` 컬럼으로만 표시**하며, 최종 결과에서 제외 여부는
분석 단계에서 결정한다.

## 알려진 제한사항

- **재수집 로직 미검증**: 현재까지는 정책전/정책후 각 1회씩만 수집한 상태라 실제 재수집
  케이스에서의 동작은 검증되지 않음. 다음 수집 시점에 확인 필요.
- **그룹 IQR의 트레이드오프**: 구×면적구간 그룹이 잘게 나뉠수록 정상 거래를 이상치로 오탐하는
  경우는 줄지만, 최상위 럭셔리 세그먼트처럼 그룹 자체가 고가로 형성된 경우 그룹 내부의 진짜
  극단값을 놓칠 수 있음.
- **`near_duplicate_candidates`는 자동 판단하지 않음**: 층만 다르고 나머지가 같은 경우를
  전부 리포트하므로, 신축 단지의 정상적인 집단 등기(같은 날 같은 가격의 다수 거래)도 포함되어
  있음. 개별 확인 필요.
- **표본 크기**: `gu_dong_month_avg_price.csv`에서 거래건수가 적은 셀(3건 이하)이 다수 존재.
  변동률(%) 계산 시 최소 표본 기준 필터링을 별도로 적용해야 함.
